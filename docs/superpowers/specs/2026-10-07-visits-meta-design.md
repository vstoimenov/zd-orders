# Посещения + Meta реклами (части 3 и 4)

Дата: 2026-10-07 · Статус: одобрен (Meta по вариант А — ID на рекламния акаунт + System User token с ads_read).

## Посещения
- `kurier.js` (на всички страници на магазина) праща при всяко зареждане `sendBeacon` към `POST /api/visit` (нова публична функция; общо 8): път, query (UTM/fbclid/gclid/ttclid), referrer.
- Сървърът: само позволени произходи (ALLOWED_ORIGINS); ботове по User-Agent се игнорират; посетител = sha256(дневна сол + сайт + IP + UA) (16 знака) — солта се сменя всеки ден (HMAC от тайна + дата по София), IP/UA не се пазят; без бисквитки.
- Източник: utm_source → иначе fbclid/gclid/ttclid → иначе домейн на referrer (google/facebook/instagram/tiktok/youtube/…); вътрешен или празен referrer → „direct“. Кампания = utm_campaign. Устройство: mobile/tablet/desktop.
- `zd.visits` (ден, сайт, посетител, път, източник, кампания, устройство); пазят се 400 дни (чистене в нощния cron).
- Поръчка от чекаута получава `traffic_source` = първият източник на същия посетител за деня.
- Табло: „Посещения“ = уникални посетители по дни (сбор), „CR“ = поръчки ÷ посещения; таблица „Източници“: посещения, поръчки, CR.

## Meta реклами
- Интеграция `meta` в zd.integrations: ID на рекламен акаунт (само цифри, без act_), токенът — криптиран. При запис: проверка `GET /v26.0/act_<id>?fields=name,currency,account_status`.
- Данни: `GET /act_<id>/insights?level=account&time_increment=1` — разход, показвания, кликове, покупки (purchase/omni_purchase) и стойност → `zd.ad_spend` (платформа, акаунт, ден). Нощно: последните 7 дни; ръчно по дати.
- Валута: EUR както е; BGN → ÷ 1,95583; друга — без превръщане, с предупреждение.
- Табло: Рекламен разход, ROAS (оборот ÷ разход), CPA (разход ÷ поръчки), CPM, POAS (печалба ÷ разход); рекламният разход се вади в „Печалба преди ДДС“.
- Грешки на Meta на български (невалиден/изтекъл ключ, няма достъп до акаунта, лимит).
