# Fulfilment (склад изпълнител) — design (approved in chat 2026-10-23)

A shop that keeps its goods at a fulfilment warehouse connects the warehouse's system to Ordyx. Ordyx sends the warehouse
each order that is ready to ship, the warehouse packs it, makes the waybill with its own courier account and tells Ordyx the
waybill number and the parcel's progress. Ordyx stops making waybills for that shop. One generic integration: no code per
warehouse — a warehouse that wants a specific integration writes to us (line on the landing and on the developer page).

Owner's words: „остави го само като интеграция и които иска интеграция с конкретен център да пише“; orders go to the
warehouse after the customer confirms (switchable to „веднага“).

## Goals
- A shop with a warehouse gets its confirmed orders there within seconds, signed, with everything the warehouse needs to pack
  and ship: customer, phone, items with SKU, delivery type, office or address, total, payment method.
- The warehouse's waybill shows in Ordyx like any other: the admin sees number, courier and status; the buyer's order page
  tracks it; a WooCommerce/custom site gets its usual „shipped“ callback.
- The warehouse only ever gets confirmed orders (unless the shop chooses „веднага“), and hears when an order it already has
  is cancelled.
- Nothing breaks for shops without a warehouse.

## Non-goals (now)
- Stock sync with the warehouse, returns handling, invoices, per-warehouse adapters, a warehouse marketplace.
- Changing the order after it was sent (an office change later is a separate feature on the roadmap).

## Anti-goals
- A warehouse receiving unconfirmed or cancelled orders and shipping them.
- A lost order: an order that is „ready“ but never reached the warehouse without anyone seeing it.
- Ordyx making a second waybill for an order the warehouse already ships.

## Pieces

### Integration `fulfilment` (per shop, zd.integrations provider `fulfilment`)
- config: `{ url, enabled, sendOn: 'confirmed' | 'new', keyId, lastSentAt, lastReceivedAt, lastError }`.
  `url` must be https (any host; the warehouse is not the shop's domain). `sendOn` default `'confirmed'`.
- secret (sealed with lib/secretbox.js): the fulfilment key `ordyx_ful_<keyId 10>_<32 base64url>`, generated by Ordyx and
  shown once (same pattern as the shop key in lib/shop-keys.js). „Нов ключ“ replaces it; the old one stops at once.
- The same key signs what Ordyx sends (HMAC) and authenticates what the warehouse sends back (Bearer).
- Admin actions (lib/admin/integrations.js): `ful_save {url, sendOn}` (validates, enables), `ful_key` (new key, shown
  once), `ful_pause` (`enabled = false`: nothing new is sent, Ordyx waybills come back for orders never sent, the key keeps
  accepting the warehouse's reports so parcels in flight are recorded), `ful_disconnect` (deletes the integration and the
  key; allowed only when no sent order is still unshipped, else „N поръчки са при склада и още не са изпратени“),
  `ful_resend` (retries the shop's due events now, 10 s budget), `ful_test` (POST `{api:1, event:'ping'}` to the url, signed;
  2xx = „Връзката работи“). Status comes with the integrations status payload as `status.fulfilment`:
  `{ enabled, url, sendOn, keyId, lastSentAt, lastReceivedAt, lastError, due }` (`due` = orders waiting to be sent).

### Orders → warehouse (lib/fulfilment.js)
- New columns on zd.orders (migration 026): `fulfil_sent_at timestamptz null`, `fulfil_notify text not null default ''`
  (the event waiting to be sent: `'order'` or `'cancelled'`), `waybill_external boolean not null default false`,
  `waybill_track_url text not null default ''`.
- `due(o, cfg)`: an order is due when the shop's integration is enabled, `fulfil_sent_at is null`, `waybill_number = ''`, and
  status is `confirmed`, or `new` when `sendOn = 'new'` **or the order needs no confirmation** (`payment_method <> 'cod'`: a
  paid card/bank order never gets a confirmation request and stays `new`); never when cancelled or `cb_check = 'pending'`.
  Duplicates (`is_duplicate`) are sent like any other order — the flag is a warning for the shop, as it is for waybills — and
  the body carries `"duplicate": true` so the warehouse can hold it.
- `queueFulfilment(q, orderId)`: called from every place an order becomes confirmed or is created — `answerConfirm` (yes),
  `voiceResult` (yes), WhatsApp button yes, admin status PATCH to `confirmed`, `startOrder`/keyed/manual/CSV creation (when
  `sendOn = 'new'`), the ConvertBuilder sync. It checks `due`, sets `fulfil_notify = 'order'` and tries `sendEvent` at once.
  Never throws; a failure leaves `fulfil_notify` set.
- `queueCancel(q, orderId)`: when an order with `fulfil_sent_at` is cancelled (admin PATCH, answerConfirm no, site cancel) →
  `fulfil_notify = 'cancelled'` and one try; once the warehouse took the cancel, `fulfil_sent_at` is cleared so an order the
  admin re-opens (PATCH back to confirmed) is sent again as a fresh `order`. An order never sent is just not sent (its
  `fulfil_notify` is cleared).
- Once `fulfil_sent_at` is set, the order is frozen like a shipped one: `upsertExternalOrder` and `upsertCbOrder` keep the
  items, address and total Ordyx already sent (same rule as `waybill_number <> ''`); a site that re-sends a changed order gets
  409 as it does for a shipped order.
- `sendEvent(q, orderId)`: builds the body, POSTs to `url` with `X-Ordyx-Timestamp` / `X-Ordyx-Signature`
  (HMAC-SHA256 of `${ts}.${body}` with the key — `signBody` from lib/woo-callback.js), `redirect: 'manual'`, 5 s timeout.
  2xx → `fulfil_sent_at = now()` (for `'order'`), `fulfil_notify = ''`, `lastSentAt`, `lastError = null`. Anything else →
  `lastError` in Bulgarian („складът отговори 500“, „складът не отговаря“, „складът пренасочва“), `fulfil_notify` stays.
- Body for `event: 'order'`:
  ```json
  { "api": 1, "event": "order", "order": {
      "id": "<uuid>", "number": "<cb_order_id>", "created_at": "<iso>", "status": "confirmed",
      "customer": { "name": "", "phone": "<phone_norm>", "email": "" },
      "delivery": { "type": "econt_office", "courier": "econt",
        "office": { "id": "econt:4001", "code": "4001", "text": "<office_text>" } | null,
        "address": { "city": "", "post_code": "", "street": "" } | null },
      "items": [ { "sku": "", "name": "", "qty": 1, "price": 0 } ],
      "total": 0, "currency": "EUR", "payment": { "method": "cod", "cod_amount": 0 },
      "tracking_page": "https://app.ordyx.eu/p/<token>" } }
  ```
  `office` for office/locker types, `address` for address types, both null for `other` (then `delivery.text` carries
  `office_text`). `cod_amount` = total for `cod`, 0 otherwise. Items come from `items` (sku, name, qty, price); an item
  without `sku` gets it from the shop's inventory (zd.product_costs) by exact product name when there is one, else `""` —
  the order is sent either way. `"duplicate": true` is added when `is_duplicate`.
- Body for `event: 'cancelled'`: `{ "api": 1, "event": "cancelled", "order": { "id", "number" } }`.
- `retryDue(q, { shopId = null, budgetMs })`: every order `due()` matches or with `fulfil_notify <> ''`, of enabled shops,
  created in the last 30 days, oldest first; stops at the budget; a shop whose warehouse fails once is skipped for the rest of
  the run (as `retryCallbacks`). Runs: nightly in api/cron/refresh.js (15 s, result key `fulfilment`), when the admin opens
  Поръчки of a shop with the integration on and `due > 0` (3 s budget, at most 5 orders, before the list is answered), and on
  `ful_resend`. `status.fulfilment.due` counts the same set. So the open orders that exist when a shop connects are not sent
  by themselves: the modal shows „N отворени поръчки чакат — изпрати ги към склада“ (`ful_resend`), and they show as „чака
  склада“ in the list until then.

### Warehouse → Ordyx (api/fulfilment.js, new Vercel function: 11 of 12)
- `POST /api/fulfilment`, `Authorization: Bearer ordyx_ful_…` (timing-safe lookup by keyId like `shopByKey`; 600/h per key
  like `overKeyLimit`). `GET` with the key → `{ ok: true, shop: <name> }` (a ping). Any other method → 405.
- Body: `{ "order_id": "<uuid>", "event": "shipped" | "delivered" | "returned" | "cancelled",
  "waybill": { "courier": "econt" | "speedy" | "boxnow" | "other", "number": "", "track_url": "" } }`.
  `order_id` must belong to the key's shop, else 404 `{ error: 'Няма такава поръчка' }`. Unknown event → 400.
- `shipped`: requires `waybill.number` (1–40 chars) and a known courier (else 400). For a cancelled order the waybill is still
  recorded (a real parcel, maybe with cash on delivery, must not vanish): status stays `cancelled`, `external_status =
  'shipped_after_cancel'`, push „⚠️ Складът изпрати отказана поръчка“, reply `{ ok: true, status: 'cancelled', warning }`.
  Otherwise it sets `waybill_number`, `waybill_courier`,
  `waybill_external = true`, `waybill_track_url` (https only, else ''), `waybill_created_at = now()`, `waybill_status =
  'Изпратена от склада'`, `waybill_demo = false`, `status = 'shipped'` (+ `status_changed_at`) when status is new/confirmed;
  then `syncStockSafe`, `notifySite(q, id, 'shipped')` (the shop's own site gets the number as for Ordyx waybills — its
  `trackUrl` is `waybill_track_url` or the courier's), push „📦 Складът изпрати поръчката“. A second `shipped` for the same
  order updates number/courier/url (the warehouse corrected it) and does not re-push. Reply `{ ok: true, status: 'shipped' }`.
- `delivered` / `returned`: only from `shipped`; sets status (+ `status_changed_at`), `waybill_status` to „Доставена“ /
  „Върната“, `syncStockSafe`. From any other status → `{ ok: true, applied: false }`.
- `cancelled` (the warehouse cannot fulfil): only while new/confirmed → status `cancelled`, `fulfil_notify = ''`, push „❌
  Складът отказа поръчката“, `notifySite(q, id, 'cancelled')`. Otherwise `applied: false`.
- Every accepted call sets `lastReceivedAt`. Errors are Bulgarian strings: `{ error }`.

### Ordyx stops making waybills for the shop
- `createWaybill`, `previewWaybill`, `assignRoute` refuse for a shop with the integration enabled, and for any order with
  `fulfil_sent_at` set whatever the integration's state (no second waybill for a parcel the warehouse may already ship):
  „Товарителниците за този магазин се правят от склада“ / „Поръчката е при склада“. `cancelWaybill` and `waybillPdf` refuse for `waybill_external`:
  „Тази товарителница е от склада — отменете я при него“. `releaseWaybill`/`confirmDrop` likewise.
- Status refresh (`refreshOrderStatus`, `syncStatuses`, nightly) skips `waybill_external` orders — the warehouse reports.
- `trackUrlOf` for the buyer page and callbacks: `waybill_track_url` when set, else the courier's URL for econt/speedy, else
  null. `lib/confirm.js` `tracking()` works unchanged with these fields (shipped step done when `waybill_created_at`).

### Admin (public/admin/index.html)
- Интеграции: card „Fulfilment склад“ (tile „FUL“, chip „свързан“/off) → modal: URL, „Изпращай към склада: при потвърждение
  от клиента (препоръчано) / веднага при постъпване“ with the hint „Ако магазинът не ползва потвърждение, изберете
  „веднага“ — иначе поръчките не тръгват“, the key shown once with copy, „Нов ключ“, „Тествай връзката“, „Изпрати
  неизпратените (N)“ when `due > 0`, „Прекъсни“. Status lines: последно изпратена / последно получена / грешка.
  The integrations status is already loaded per shop; add `fulfilment` to it.
- Поръчки: for a shop with the integration on, the „Товарителница“ button and the waybill route chooser are hidden; instead a
  chip „склад“ on orders with `fulfil_sent_at` and „чака склада“ (orange) on orders with `fulfil_notify <> ''`. An external
  waybill shows the courier + number with the track link and a small „от склада“ label; no cancel/PDF buttons. The order
  payload carries `fulfilment: { sentAt, pending }` and `shipment.external`, `shipment.trackUrl` (toOrder).
- Demo: the card shows as off with a fake „connect“ that says it is a demo (lib/demo/fakes.js) — no network.

## Constraints
- Node 22 ESM, plain Vercel functions (the new api/fulfilment.js makes 11 of 12 on Hobby), Postgres schema `zd` via the
  pooler, node:test + PGlite. No new dependencies.
- Secrets sealed with lib/secretbox.js; keys never logged; timing-safe comparisons.
- Outbound only to https; `redirect: 'manual'`; 5 s timeout; the warehouse never makes an order fail.
- Migration 026 applied by hand (Supabase MCP) before deploy; deploy with `npx vercel deploy --prod --yes`.
- Bulgarian texts in the admin and on pages; no competitor names.

## Calls made after the builder check (mine, not the owner's)
- Paid (non-COD) orders count as ready without confirmation; duplicates are sent with a flag; missing SKUs are filled from the
  inventory by name; a sent order is frozen against site/sync rewrites; a cancel that reached the warehouse clears
  `fulfil_sent_at` so a re-opened order is sent again; „Прекъсни“ pauses (key still accepts reports) and a full delete is
  only possible with nothing in flight; the backlog on connect is sent by one button; a late `shipped` for a cancelled order
  is recorded and flagged; waybill refusal is per shop and per sent order.
