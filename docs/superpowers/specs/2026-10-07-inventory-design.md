# Наличности (част 2 от 4)

Дата: 2026-10-07 · Статус: одобрен (наличността намалява автоматично при нова поръчка).

## Продукти
- Един общ списък за „Финанси“ и „Наличности“ (`zd.product_costs`): име, SKU, наличност (`stock`, празно = не се следи), праг за ниска наличност (по подразбиране 5), себестойност, `tracked_since`.
- Поръчките се свързват с продукта по име (без главни/малки букви и интервали в краищата).
- Броенето започва от въвеждането на наличност: поръчки, създадени преди `tracked_since`, не я променят.

## Автоматични движения
- Поръчката държи стока, докато не е „Отказана“ или „Върната“. Нова поръчка (чекаут, ConvertBuilder, уебхук) → −количество; отказ/връщане → +; обратно на друг статус → − отново; изтриване → +.
- Във всяка поръчка `stock_applied` пази колко е приспаднато по продукт. Синхронизацията изчислява „желано − приложено“ и го прилага с едно SQL изречение със сравни-и-смени (CAS), така че две едновременни повиквания (чекаут + уебхук) не броят двойно.
- Всяко движение се записва в `zd.stock_moves` (поръчка / връщане / ръчна корекция + бележка). Наличността може да стане отрицателна.
- Грешка в наличностите никога не проваля приемането на поръчка (записва се в лога).

## Страница „Наличности“ (раздел „Отчети“)
- Карти: Продукти (следени) · Общо налични (зелено) · Ниска наличност 0 < бр. ≤ праг (оранжево) · Изчерпани ≤ 0 (червено).
- Търсене по име/SKU; филтри Всички / Ниска наличност / Изчерпани / Не се следят.
- Таблица: продукт, SKU, наличност, праг, продадени за 30 дни, себестойност; бутони Редактирай · Корекция · История.
- „+ Създай продукт“ и „Редактирай“: прозорец с име (само при създаване), SKU, наличност, праг, себестойност. Промяна на числото за наличност се записва като ръчна корекция.
- „Корекция“: ± количество + причина (Доставка, Брак, Преброяване, Друго) + бележка. „История“: последните 50 движения.
